# Blender asset pipeline

The weapons, characters and maps in `public/models/` are generated by these
scripts. They run headless with Blender's Python module, or inside a running
Blender (for example through the Blender MCP add-on), where they build into a
separate `VantageBuild` scene and leave your other scenes alone.

```bash
python3 -m venv .bvenv && .bvenv/bin/pip install bpy==5.2.3
.bvenv/bin/python blender/weapons.py                       # all guns + knives → public/models/weapons
.bvenv/bin/python blender/characters.py                    # T and CT soldiers → public/models/characters
.bvenv/bin/python blender/map.py --map dunehold            # map mesh + colliders → public/models/maps
```

Inside Blender, add `blender/` to `sys.path`, import the module and call
`main([...])` with the same arguments, e.g. `weapons.main(['--only', 'ak47'])`.

Add `--preview` to either script to also render PNG previews (Cycles, CPU), and
`--only ak47,knife_karambit` to build specific weapons.

- `lib.py`: profile extrusion, rounded (`puffy`) extrusion, cross-section lofts,
  lathe, rails, boolean cuts, bevel and weighted-normal modifiers, ground knife
  blades and glTF export
- `weapons.py`: every gun and knife. Material name prefixes (`skin_`, `metal_`, `detail_`)
  tell the game which parts take weapon finishes (`skin_steel` is bare steel that still takes
  them, `detail_dot` is white sight paint). Empties (`muzzle`, `grip`, `fore`) are the
  anchor points, and objects named `mag`, `slide`, `bolt`, `cylinder`, `bfA`, `bfB` and
  `karambitPivot` are animated; parts that ride on a slide or bolt are parented to it, and the
  revolver's cylinder has its origin on its axis so it turns in place. Part names also pick a
  surface in the game: `chequer` or `knurl` in a name gets diamond chequering, and polymer parts
  are stippled only when named for a grip, stock or handguard. Every gun is exported with
  ambient occlusion baked into a vertex colour (`export_glb(path, ao=...)` in `lib.py`, a quick
  Cycles bake on the CPU), which the game multiplies into each part's material.
- `characters.py`: one soldier per team plus their first-person arms
  (`characters/{t,ct}.glb`, `characters/arms_{t,ct}.glb`). Built on the CC0
  MakeHuman base mesh in `assets/makehuman/`:
  - `human.py` shapes it (athletic adult man), poses it into the game's rest
    pose and maps its skin weights onto the 17 bones `src/rig.js` drives
  - `cloth.py` grows the clothing off the body (eased, relaxed over hollows,
    folded at elbows, knees, cuffs and boot tops) and lofts boots and head
    wear through measured body sections
  - `gear.py` builds the kit on top: plate carrier, cummerbund, pouches,
    magazines, belt, drop-leg holster, knee pads, helmet with rails, headset,
    glasses, the militia's chest rig
  - `texture.py` gives every part a procedural material (fabric weave,
    webbing rows, the shemagh's check, leather, rubber, worn paint) and bakes
    them into one texture set per model (colour with ambient occlusion,
    normal, roughness/metal)
  Takes about five minutes for both teams at the default 2048 px; `--size 1024`
  is quicker for trying things, `--only ct` builds one team.
- `map.py`: reads the ASCII grid in `src/maps.js` and builds walls, facades, props and floors
  with world-space UVs. Set dressing (rooftop domes, towers,
  balconies, palms, stalls, pots) uses its own random stream so the layout stays put.
  It writes `<map>.colliders.json`, which the game uses for collision.

The game loads these files at startup and falls back to its built-in procedural
models if any file is missing.
